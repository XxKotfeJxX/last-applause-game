# Архітектура

`WorldState` у `src/domain/types.ts` — єдине джерело істини. `src/domain/game.ts` створює стан, перевіряє дії, переміщує предмети, веде програму, угоди й фінал. `src/simulation/navigation.ts` містить геометрію доступних прямокутників і пошук маршруту; `tickWorld` застосовує фіксований крок 100 мс. Обидва модулі не імпортують браузер, Three.js чи Electron.

Потік: семантичний код клавіші з `src/input/map.ts` → `movePlayer` або `execute` → зміна `WorldState` і журнал → `GameScene.update` та DOM у `src/main.ts` → процедурний звук. `execute` перевіряє близькість, доступність дії та її умови; UI використовує ті самі `getOptions`. Предмет має одну `ItemLocation`; представлення створюється з неї, а не навпаки.

NPC тримають `task`, `goalNode`, `route`, `planRevision` та фазу анімації. Події мають `dueTimeMs`, ID і revision. Якщо план змінено до підбирання ножів, стара подія не переносить предмет. Видимість у камері не бере участі в `tickWorld`.

Програма — три стійкі слоти з поточними `actId`. Угода зберігає ідентичності слотів та номерів, згоду кандидата й витісненого артиста, ціну й статус. Commit повторно перевіряє стан, атомарно міняє номери та списує жетони один раз. `FinaleResolver` у `resolveFinale` дивиться на встановлені предмети й механізми, а не на прапорець переглянутої підказки.

`src/render/scene.ts` будує справжні 3D підлоги, стіни, галерею, колесо та прості декорації. Персонажі й предмети — вертикальні плоскі зображення. `src/render/assets.ts` обирає файл зі статичного `src/generated/catalog.ts` або створює CanvasTexture. UV належать окремому quad кожного актора, тому спільний атлас не синхронізує чужі кадри.

`src/persistence/save.ts` серіалізує лише `WorldState`. Графіка й звук після load будуються заново. Electron віддає тільки `dist-web` через `app://game/` із перевіркою шляху; renderer ізольований і не має Node integration. Збереження використовує стабільний origin та профіль Electron.
